# 느링고 역할극 PoC — 측정 지표

## 육하원칙

| | |
|---|---|
| **누가** | 개발자 1인. 아동은 참여하지 않았고, 아동 발화는 고정 대본이다. |
| **언제** | 턴이 끝나는 순간 한 번에. 역할극이 도는 중에는 DB를 건드리지 않는다. |
| **어디서** | SQLite 14개 테이블 → 리포트 `server/runs/<실행id>/summary.md` |
| **무엇을** | 속도 · 토큰 · 품질 · 학습효과 · 안전 · 실행조건 6축 |
| **어떻게** | 모든 AI 호출이 계측기를 필수로 받는다. 계측 안 된 호출을 만들 수 없다. |
| **왜** | 개선하려면 "개선 전"이 숫자로 남아 있어야 한다. |

### 단계 이름

한 턴은 이 순서로 돈다.

| 코드상 이름 | 우리말 | 하는 일 |
|---|---|---|
| `intake` | **발화 입력** | 아이가 쓴 말을 받아 안전한지, 목표에 가까워졌는지 판정 |
| `moderation` | **유해성 검사** | OpenAI에 따로 물어보는 2차 안전망 |
| `goal_scan` | **목표 확인** | 지금까지 대화에서 아이가 목표를 달성했는지 다시 훑음 |
| `generate` | **생성** | 캐릭터 대사와 마스코트 대사를 만듦 |
| `judge` | **판단** | 만든 대사를 아이에게 보내도 되는지 검사. 문제 있으면 되돌림 |

## 1. 속도

### 시간이 여러 개인 이유

같은 턴을 세 군데서 잰다. 어디를 고쳐야 하는지가 달라서다.

| 시계 | 재는 구간 | 실측(중앙값) |
|---|---|---|
| ① 왕복 | 화면이 요청을 보내고 답을 받을 때까지 **전부** | 9,187ms |
| ② 파이프라인 | 서버 안에서 AI를 부르는 구간만 | 9,166ms |
| ③ 단계별 | 발화 입력·판단 같은 **개별 AI 호출 하나하나** | 판단 3,788ms 등 |

**① − ② = 17ms** (평균 19ms, 가장 나쁠 때 106ms). 283턴 기준.
이게 AI를 뺀 나머지 — 서버가 데이터를 포장하고, DB에 기록하는 데 쓴 시간이다.
**전체의 0.15%.** 즉 느린 원인은 서버도 네트워크도 아니고 **전부 AI 호출**이다.

> 단, 시뮬레이션을 서버와 같은 컴퓨터에서 돌려서 인터넷 구간이 빠져 있다. 실제 아동이 밖에서 접속하면 ①은 더 커진다.

| 지표 | 무엇을 설명하는가 | 실측 |

| 되돌린 이유 분포 | 무엇 때문에 다시 만들었나 | 캐릭터가 질문을 중복한 경우 32건 |
| 없는 이유를 지어낸 비율 | 판단 AI가 정해진 기준을 벗어났나 | 발생 중 |
| 정해진 말로 내려간 비율 | 3번 다 실패해서 미리 준비한 문구를 내보낸 비율 | 22% |
| **일부 단계가 죽은 턴** | 아래 설명 참고 | 20턴 (295턴 중) |

### "일부 단계가 죽은 턴"이 무슨 뜻인가

AI 호출 하나가 실패했는데 **역할극은 멈추지 않고 계속 진행된 턴**이다. 실측 20턴의 내용:

- **발화 입력이 죽은 턴 10건** — 아이 말이 안전한지 판정하지 못한 채 그냥 진행됐다. 유해성 검사(OpenAI)가 2차로 막아 주지만, 1차 그물이 빠진 상태다.
- **발화 입력 + 목표 확인이 둘 다 죽은 턴 10건** — 위에 더해, 아이가 목표를 달성했는지도 확인하지 못했다. 아이가 정답을 말했어도 인정되지 않는다.

에러를 내고 멈추는 대신 계속 가도록 만든 것은 의도한 설계다(아이 앞에서 오류 화면을 띄우지 않는다). 다만 **그 대가가 몇 번 발생했는지는 세어 둬야** 한다. 이 숫자가 커지면 안전망이 실제로는 한 겹뿐이라는 뜻이다.
